# 前言
当你在浏览器中输入一行URL时会发生什么呢？

# HTTPS 预处理
现代浏览器都需要经过HTTPS加密访问，很少出现使用HTTP裸连的情况，所以浏览器会检查本地的HSTS表，查看域名是否使用HTTPS，如果是，则自动将HTTP连接变为HTTPS连接。

## HSTS 
HSTS列表会经过两种方式加载：
### 1. 动态记录（本地缓存）

这是最基础的 HSTS 机制。

原理：当你第一次通过 HTTPS 安全地访问某个网站时，服务器会在 HTTP 响应头中返回一个 Strict-Transport-Security 字段（例如：Strict-Transport-Security: max-age=31536000; includeSubDomains）。

本地存储：浏览器收到这个响应头后，会将这个域名以及过期时间（max-age）记录在浏览器本地的用户数据目录中（相当于一种特殊的本地缓存数据库）。

特点：它是动态增长的。你访问开启了 HSTS 的新网站越多，你本地的这个列表就越长。由于它依赖于“第一次访问”，所以存在一个被称为“首次访问安全漏洞”的弱点（即第一次建立连接时如果没用 HTTPS，仍可能被劫持）。

### 2. 预加载列表（HSTS Preload List）

为了解决动态记录“首次访问不安全”的问题，诞生了预加载列表机制。

原理：这是一个由 Google 维护的全球性的公开列表（hstspreload.org）。网站管理员可以主动将自己的域名提交到这个列表中。

本地存储：主流浏览器厂商（包括 Chrome、Firefox、Safari、Edge 等）会定期拉取这个列表，并将其直接硬编码（打包）到浏览器的源代码/安装包中。

特点：当你下载或更新浏览器时，这个庞大的列表就已经存在于你的本地硬盘上了。这就意味着，即使你是第一次访问这些域名，浏览器也能直接在本地源码列表中找到它，并强制使用 HTTPS，实现了绝对的“首次访问安全”。

### 3. 当HTTP请求不在HSTS表中发生什么？
分为三种情况：
1. 服务器配置了重定向。当浏览器使用不安全的 HTTP 向网站发起请求，网站服务器接收到请求，但它不希望你使用不安全的连接，于是返回一个 `301`（永久重定向） 或 `302`（临时重定向） 状态码，并在响应头的 Location 中写上对应的 `https://...` 地址。同时，服务器通常也会在这个重定向（或随后的 HTTPS 响应）中携带 `Strict-Transport-Security` 响应头。

2. 服务器未配置重定向。当浏览器使用不安全的HTTP 向网站发起请求，网站会正常显示，但会继续使用不安全的 HTTP。此时浏览器地址栏通常会显示一个灰色的“不安全（Not Secure）”警告图标。由于没有经过合法的 HTTPS 连接，服务器无法向浏览器成功写入 HSTS 规则。

3. 服务器关闭了`80（HTTP）`端口，仅监听`443（HTTPS）`端口。无法建立TCP连接，浏览器会显示“无法访问此网站”或“连接被拒绝”（ERR_CONNECTION_REFUSED），网站拒绝了你的访问。它不会自动尝试改用 HTTPS 端口访问，除非你手动在地址栏加上 `https://`。

# DNS解析
浏览器经过HTTPS预处理后，会查询域名对应的IP地址。

分为以下四种途径：
1. 浏览器缓存：先看浏览器缓存内是否有对应的IP地址。
2. 操作系统缓存：再看Hosts文件中是否有写死的IP地址。
3. 递归查询/迭代查询：操作系统向本地DNS服务器**递归查询**`www.google.com`，本地DNS向根域名服务器（根域名告诉本地DNS去`.com 顶级域名服务器查`）->顶级域名服务器->权威域名服务器**迭代查询**
