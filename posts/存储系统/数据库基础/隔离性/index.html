数据库事务隔离性与隔离级别

隔离性（Isolation）

在 ACID 特性中，隔离性（Isolation）用于约束并发事务之间的相互影响程度。

数据库系统为了兼顾并发性能与数据一致性，并非在所有场景下都强制要求最高级别的隔离，而是通过定义不同的隔离级别（Isolation Level），对事务间的数据可见性和并发异常做出不同程度的保证。

SQL-92 标准隔离级别

SQL 标准依据并发执行可能引发的典型异象（Phenomena），定义了四种隔离级别：

隔离级别 脏读（Dirty Read） 不可重复读（Non-repeatable Read） 幻读（Phantom Read）
读未提交（Read Uncommitted） 可能 可能 可能
读已提交（Read Committed） 杜绝 可能 可能
可重复读（Repeatable Read） 杜绝 杜绝 可能*
串行化（Serializable） 杜绝 杜绝 杜绝

[!NOTE]
关于 MySQL 与幻读的说明：
SQL-92 标准中的“可重复读”允许出现幻读。在实现层面，MySQL InnoDB 引擎通过 MVCC（多版本并发控制）+ Next-Key Lock（记录锁与间隙锁） 极大程度缓解了幻读：

  • 纯快照读（Snapshot Read）：通过 Read View 保证多次读取版本一致，避免了快照读下的幻读。
  • 当前读（Current Read）：通过 Next-Key Lock 阻塞插入操作来杜绝幻读。
  • 例外情况：若事务 A 先执行快照读，期间事务 B 插入新行并提交，随后事务 A 对该新行执行 UPDATE 并再次快照读，此时新行会被纳入 A 的可见视图中，仍会出现幻读。因此严格来说，InnoDB 在 RR 级别并未 100% 杜绝所有边界场景下的幻读。

1. 读未提交（Read Uncommitted）

该级别是隔离性最弱的模式。事务可以读取到其他并发事务尚未提交的数据修改。

核心异象：脏读（Dirty Read）

  • 定义：一个事务读取到了另一个并发事务尚未提交的修改，且该修改随后被回滚。
  • 时序示例：
    1. 事务 B 修改某行记录（未提交）。
    2. 事务 A 读取该行，获取到被修改后的值。
    3. 事务 B 发生异常并执行 ROLLBACK。
    4. 事务 A 此时基于一条在逻辑上从未真实存在的数据完成了后续操作。

2. 读已提交（Read Committed）

事务只能读取到其他事务已经提交的数据变更，读未提交的数据对外部不可见，从而彻底杜绝了脏读。

核心异象：不可重复读（Non-repeatable Read）

  • 定义：同一事务内，前后两次读取同一条已有记录，读取到的数据值不一致。
  • 时序示例：
    1. 事务 A 读取记录 $X$ 的值（值为 10）。
    2. 事务 B 将记录 $X$ 的值修改为 20，并提交事务。
    3. 事务 A 再次读取记录 $X$，读到修改后的值 20。
  • 原因：在读已提交级别下，每次执行查询语句都会重新生成一次数据可见性视图（Read View），因此能感知到外部刚提交的修改。

3. 可重复读（Repeatable Read）

保证在同一事务生命周期内，多次读取同一条记录的结果保持一致，不受其他事务提交修改的影响。

核心异象：幻读（Phantom Read）

  • 与不可重复读的本质区别：
    • 不可重复读关注的是既有记录的更新（Update / Delete）。
    • 幻读关注的是范围查询下记录数量的增减（Insert）。
  • 定义：同一事务内，使用相同的条件进行范围查询，后续查询读取到了并发事务新插入并提交的记录，导致返回的结果集行数发生了改变。
  • 时序示例：
    1. 事务 A 执行范围查询 SELECT * FROM orders WHERE amount > 100，匹配到 5 条记录。
    2. 事务 B 插入了一条 amount = 150 的新记录并提交。
    3. 事务 A 再次执行相同范围查询，结果集变为了 6 条。

4. 串行化（Serializable）

SQL 标准中最高的隔离级别。要求并发执行的事务在效果上完全等价于某种串行执行的次序（Serial Schedule）。

  • 并非单线程串行执行：系统内部依然允许并发与交错执行，但通过严格的锁协议（如两阶段锁 2PL）或可串行化快照隔离（SSI, Serializable Snapshot Isolation）对读写冲突进行检测。
  • 一致性代价：若检测到事务之间的执行图存在环路（无法等价于任何一种合法的串行顺序），数据库引擎会主动中止并回滚其中冲突的事务，以牺牲吞吐量和并发度为代价换取绝对的正确性。

隔离性的底层支撑：MVCC 简述

MVCC（Multi-Version Concurrency Control，多版本并发控制） 是现代关系型数据库（如 MySQL、PostgreSQL）实现高并发读写、避免读写互相阻塞的关键机制。

  • 核心思想：
    • 数据更新不直接原地覆盖物理记录，而是以版本链的形式保留历史版本（如配合 Undo Log）。
    • 读操作通过构建事务启动时的可见性判断规则（Read View / 快照），只读取对自己可见的历史版本，实现读写不冲突。
  • 应用对应：
    • RC 级别：每次查询都生成新的 Read View。
    • RR 级别：事务内首次查询时生成 Read View，并在整个事务周期内复用该视图。

(详细可见性对比算法与版本链流转见后续 MVCC 专章)
